## 같은 PC와 원래 작업 폴더가 보존된 경우

Windows PowerShell에서 기존 `rh-reduced/source-build` 디렉터리로 이동해 아래를 실행한다. Python 3.11 이상과 기존 격리 작업 공간을 사용한다. `public-checkpoint`의 이 문서·매니페스트·재개 도우미가 원래의 `source-build` 바로 아래에 있어야 한다.

```powershell
Get-FileHash .\public-checkpoint\checkpoint-manifest.json -Algorithm SHA256
py -3 -I -B -X utf8 .\public-checkpoint\resume_source.py
```

첫 명령의 값이 표와 일치하는지 확인한다. 도우미는 기존 worker 잠금을 검사한다. 이미 실행 중이면 PID를 추가하지 않는다. 종료된 상태이면 첫 200개 체크포인트를 검산한 뒤 `compile_compact.py`를 새로 시작하고 `finish_source.py`를 그 PID에 연결한다. 빌드 감독은 로컬 `receipts/modules.jsonl`에 완전히 기록된 **200개 이후 모듈도** 저장된 산출물 해시와 대조해 이어 간다. 완료하지 못한 모듈은 원래 `.lean`에서 다시 컴파일한다. 진행 중이던 프로세스의 메모리 상태는 운영체제가 종료될 때 사라진다.

재개에 필요한 로컬 자료는 `compact`, `source-order.json`, `source-review.json`, `official-tool.json`, `official-pins.json`, `lean-4.35.0-windows`, 캐시가 준비된 `mathlib`, `cache-get.log`, `verified-lib`, `receipts`, `commands`, `setup`, `scratch`, `exports`와 세 감독 코드 `compile_compact.py`, `restricted_compact.py`, `finish_source.py`다. 로컬 명령 기록과 NTFS 권한은 원래 위치에 보관한다. 실제 운영체제 경로가 바뀌면 기존 원로그의 경로 대조에는 원래 작업 공간이 필요하다. 원래 사용자 프로필에서 공식 proof 입력·SDK·완료된 라이브러리는 격리 프로세스가 읽을 수 있고, `scratch`에만 새 결과를 쓸 수 있어야 한다. 이 권한은 Git 스냅샷으로 전송되지 않는다.

## 공개 파일만 남은 경우

공개 해시 목록에서 `.olean` 바이트를 복구할 수 없다. 새로운 컴퓨터에서는 고정된 Git 소스·공식 Lean 릴리스·공식 Mathlib 핀/캐시를 다시 준비하고 전용 작업 공간의 격리를 확인한 뒤 소스에서 시작해야 한다. 공개 `.olean` 캐시를 읽은 확인 결과와 자신이 소스를 재컴파일한 건수는 별도로 기록한다. [고정 소스](https://github.com/lsernau/grh-lean/tree/72fead102f663d5c7a407964a13dc0cf9d977207/grh-compact) · [공식 Lean 릴리스](https://github.com/leanprover/lean4/releases/tag/v4.35.0) · [MIT 공개 자료](https://math.mit.edu/~drew/shortgrh/)

최종 소스 판정은 로컬 `receipts/source-terminal.json`과 `소스-종료판정.md`에 기록한다. `sourceMainBuilt`는 재컴파일 794개, `axioms`는 실제 다섯 `#print axioms`, `solution`은 재생성한 증명 export의 원시 해시를 뜻한다. 독립 커널의 전체 수락 여부는 별도 커널 원로그의 다섯 목표 및 종료 코드로 확인한다.
